# AI arbitration decision model

Эта заметка фиксирует будущую механику AI-арбитража. Сейчас это не реализовано в коде.

## Главная идея

Qwen должен не просто красиво отвечать на приказ игрока. Он должен анализировать, возможно ли действие в текущем положении государства, насколько оно разумно, какие риски несет и какие последствия должно дать миру.

Важно различать два случая:

- **Действие невозможно.** У государства нет ресурсов, армии, доступа к региону, дипломатического канала, права владения или физической возможности выполнить приказ. Такой ход блокируется.
- **Действие возможно, но плохое.** Государство может попытаться выполнить приказ, но решение необдуманное, рискованное или политически вредное. Тогда ход не блокируется автоматически, но последствия могут ударить по игроку.

## Роль движка и AI

Движок должен проверять жесткую допустимость:

- есть ли нужные ресурсы;
- существует ли цель;
- доступен ли регион;
- принадлежит ли игроку фракция;
- открыт ли ход;
- не нарушает ли приказ базовые guardrails;
- допустим ли тип структурного эффекта.

Qwen должен оценивать смысл и качество решения:

- разумность приказа;
- масштаб действия;
- военный, экономический и дипломатический риск;
- реакцию других стран;
- вероятность успеха;
- цену ошибки;
- последствия для ресурсов, войск, стабильности, дипломатии и хроники.

## Пример логики

Если игрок отправляет неподготовленную армию в рискованное наступление, и у страны технически есть армия и возможность атаковать, приказ может быть принят как возможный. Но Qwen может определить его как необдуманный и вернуть тяжелые последствия:

- потеря войск;
- потеря ресурсов;
- ухудшение дипломатии;
- провал операции;
- рост нестабильности;
- событие в хронике о неудачном решении.

Это делает игру живой: игрок не просто ищет кнопку успеха, а думает как правитель.

## Рекомендуемые категории результата

- `impossible` - действие невозможно при текущем состоянии.
- `possible_safe` - действие возможно и разумно.
- `possible_risky` - действие возможно, но с заметным риском.
- `possible_reckless` - действие возможно, но решение плохое и может привести к ущербу.
- `partial_success` - часть цели достигнута, но есть цена.
- `failure_with_consequences` - действие выполнено или предпринято, но результат негативный.

## Черновой контракт AI-решения

```ts
type AiActionJudgement =
  | 'impossible'
  | 'possible_safe'
  | 'possible_risky'
  | 'possible_reckless'
  | 'partial_success'
  | 'failure_with_consequences';

type AiArbitrationDecision = {
  feasibility: 'blocked' | 'attemptable';
  judgement: AiActionJudgement;
  riskLevel: 'low' | 'medium' | 'high' | 'critical';
  reasoningSummary: string;
  playerFacingResult: string;
  engineEffect: {
    kind:
      | 'blocked'
      | 'event-only'
      | 'create-order'
      | 'diplomacy-action'
      | 'enact-law';
    resourceDelta?: Record<string, number>;
    diplomacyDelta?: Record<string, number>;
    armyDelta?: Record<string, number>;
    stabilityDelta?: number;
    eventText?: string;
  };
};
```

## Правило применения

AI не должен напрямую менять произвольные поля состояния. Он предлагает структурированный `engineEffect`, а серверный движок валидирует и применяет только разрешенные эффекты.

Базовая схема:

```ts
if (!engineCanAttempt(action, state)) {
  return blockedDecision;
}

const aiDecision = await qwenJudgeAction(action, state);
const normalized = normalizeAiDecision(aiDecision);
const validated = validateEngineEffect(normalized.engineEffect, state);

applyValidatedEffect(validated);
```

## Для будущей реализации

Когда начнется работа над AI-слоем, эту заметку нужно превратить в:

- runtime schema validation для ответа Qwen;
- tests для impossible/risky/reckless действий;
- server-side authoritative apply;
- audit log с raw AI output, normalized decision и applied effect;
- UI-блок, показывающий не только текст результата, но и примененный структурный эффект.
